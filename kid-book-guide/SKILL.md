# 童趣名著导读（单页 HTML）

## 概览

把一本"孩子读不懂"的书，产出一份能独立看懂的**单个 HTML 文件**：奶油纸质底色、粉彩贴纸卡片、手绘风 SVG 插画、可折叠的章节卡。
一份成品通常 60–70KB，双击即可离线打开，也可以直接发给家长。

固定 12 个板块，顺序本身是教学法（先给结论 → 认人 → 看图 → 读细节 → 交给家长）：

> 封面 · 三句话讲完 · 人物档案 · 主图 · 五/六幕 · 章节地图 · 小百科 · 对比表 · 金句 · 想一想 · 小词典 · 给家长

## 何时使用

- 用户要把小说、传记、历史事件、纪录片、长报告讲给 8–14 岁的孩子听。
- 用户要"章节故事 + 流程 + 人物关系"这类结构化梳理，并希望好看、能分享。
- 需要做成**系列**（三部曲/多册），要求风格统一、互相链接。

不适用：成人向的深度文学评论、需要引用原文大段节选（版权）、需要交互应用或后端。

## 工作流

### 第 1 步：定边界（不确认就不要动笔）

向用户确认三件事，缺一项就用括号里的默认值并说明：

1. **覆盖范围**（默认：只写用户点名的这一册，绝不剧透续作）
2. **目标年龄**（默认：10–12 岁）→ 决定内容粒度
3. **输出位置与文件名**（默认：当前目录，`{作品}{部次}-{书名}-小小读者导读.html`）

年龄对应的处理粒度、以及"沉重内容"的三层降级写法，见 `references/content-playbook.md` 第一节。

### 第 2 步：搭骨架

```bash
cp ~/.workbuddy/skills/kid-book-guide/assets/template.html \
   "/abs/输出目录/{作品}{部次}-{书名}-小小读者导读.html"
```

模板已内联全部 CSS（含人物卡、面壁者式档案卡、童话卡、公式卡、折叠章节卡、对比表、深色金句卡、终章卡、系列导航卡），**不要新建 CSS 文件、不要引外部字体**。

### 第 3 步：换主色（系列感靠这一步）

只改主色三件套，其余令牌不动（见 `references/design-system.md` 第二节）：

| 气质 | 主色 | 软底 |
|---|---|---|
| 好奇、谜团 | `#7C6BFF` 紫 | `#EFEBFF` |
| 森林、博弈 | `#2F7A63` 墨绿 | `#E4F5EE` |
| 时间、告别 | `#B2832C` 暗金 | `#FBF0D4` |
| 远航、冷静 | `#2B6CB0` 海蓝 | `#E3F0FB` |

标题高亮条**始终保持黄→粉渐变**，不随主色变——这是系列视觉签名。

### 第 4 步：写内容

按 `references/content-playbook.md` 的 12 节结构与 12 条改写规则填。写之前先把人物表和主线列成两行清单，避免边写边想。

三条最容易翻车的规则，单独强调：

1. **不编造**身份、动机、对话。记不清就写"计划被当面说穿"这种留白句——细节越具体，可信度越低。
2. **每个情节双段式**：`发生什么`（事实）+ `为什么重要`（后果）。只有事实的文档孩子读不下去。
3. **每个抽象概念配一个 10 岁孩子能懂的生活类比**（压缩解压、玻璃房、书被压成纸、火鸡科学家）。

### 第 5 步：画主图

先判定要讲"关系"还是"机制"：关系用放射图（≤6 节点），机制用横向流程（≤5 步），前后变化用左右并置同一组元素。
选型规则与容量红线见 content-playbook 第四节；**用 HTML 还是 SVG** 的判定见 design-system 第四节（关键判据：手机上最长文字是否会小于 9px）。

### 第 6 步：QA 与交付

```bash
# 结构/链接/单文件自检（必须 0 error）
python3 ~/.workbuddy/skills/kid-book-guide/scripts/check_page.py "/abs/page.html"

# 首屏截图（macOS / Edge，Chrome 同参数）
"/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge" \
  --headless=new --no-sandbox --disable-gpu --hide-scrollbars \
  --virtual-time-budget=2500 --window-size=1200,2600 \
  --screenshot=/tmp/p_top.png "file:///abs/page.html"
```

然后按 design-system 第七节的清单目视检查：高亮条在不在、中文有没有被截断、SVG 文字是否可读、水印有没有压字、表格是否内部滚动、深色卡文字是否为浅色。
最后用 `present_files` 交付，并在回复里说明：覆盖范围、建议年龄、以及这一册的"儿童入口"是什么。

## 系列化规则

- 文件名统一 `{作品}{部次}-{书名}-小小读者导读.html`，保证同目录下按名称排序正确。
- 每册主色不同，其余完全一致；上一部/下一部用导航胶囊互链，最后一册底部加"系列导航卡"（当前册标 `.now` 且不可点）。
- 每册都要能**单独看懂**，不依赖前一册；跨册只在"给家长"里给阅读顺序建议。

## 常见失败模式

| 症状 | 原因 | 修法 |
|---|---|---|
| 页面很漂亮但孩子读不下去 | 只有"发生什么"，没有"为什么重要" | 每条情节补一句后果 |
| 家长不敢给孩子看 | 没交代沉重内容与适读年龄 | 写具体的"沉重清单"，不写"含少量暴力" |
| 图看不懂 | 把整段说明塞进 SVG `<text>` | 文字转 HTML 组件，图只留 6 个节点内的关键词 |
| 手机上一团糟 | 表格没包 `.tablewrap`、SVG 文字过小 | 跑 `check_page.py`；关键信息改 CSS 组件 |
| 内容被质疑不准确 | 为了生动补了记不清的细节 | 模糊化或删掉，宁可留白 |
| 三个板块讲同一件事 | 没有先列人物/主线清单 | 合并功能重复的人物，一人只承担一个功能 |
